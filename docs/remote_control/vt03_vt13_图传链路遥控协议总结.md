# VT03/VT13 图传链路遥控协议总结

文档更新日期：2026-07-19

本文用于给机器人开发板侧实现提供统一依据，结合以下两份官方文档：

1. `RoboMaster 2026 机甲大师高校系列赛通信协议 V1.2.0（20260209）`
2. `RoboMaster 裁判系统相机图传模块 VT03&VT13 使用说明书（2025.04）`

---

## 1. 文档边界与“看起来不一致”的原因

两份文档描述的是不同层级：

1. **通信协议 V1.2.0**：比赛系统接口层（命令字、频率、MQTT/Protobuf、UDP视频流）。
2. **VT03&VT13 使用说明书**：设备物理层（对频、指示灯、UART 21字节遥控帧、CRC）。

机器人板端做“图传遥控解包”时，**以 VT03&VT13 手册中的 UART 遥控帧为直接依据**。  
涉及自定义客户端/图传上层交互（`0x0310/0x0311`）时，再参考通信协议文档。

---

## 2. 图传链路拓扑（机器人侧视角）

### 2.1 硬件遥控链路

1. 操作手在接收端或选手端产生控制输入（摇杆/按键/键鼠）。
2. 接收端通过图传无线链路传递给发送端。
3. **发送端通过 UART 输出 21B 遥控帧给机器人主控**。
4. 机器人主控解析后转为底盘/云台/发射命令。

### 2.2 自定义客户端链路（上层数据）

1. 自定义客户端通过 MQTT/Protobuf 接入图传服务器。
2. 通过 topic 指令与机器人交换上层自定义数据（如 `CustomControl`）。
3. 该链路是“上层业务数据交互”，不等同于底层 UART 21B 遥控帧。

---

## 3. 发送端 UART 遥控帧协议（机器人端核心）

### 3.1 串口参数

1. 波特率：`921600`
2. 数据位：`8`
3. 停止位：`1`
4. 校验位：无
5. 流控：无
6. 发送周期：约 `14ms/帧`
7. 帧长：`21 字节`

### 3.2 帧结构总览

1. 帧头：`0xA9 0x53`
2. 数据域：通道、开关、按键、键鼠
3. 帧尾：`CRC16`（2B）

### 3.3 通道与按键定义（按手册位偏移）

1. `ch0`（11bit）：右摇杆水平，范围 364~1684，中值 1024
2. `ch1`（11bit）：右摇杆竖直，范围 364~1684，中值 1024
3. `ch2`（11bit）：左摇杆竖直，范围 364~1684，中值 1024
4. `ch3`（11bit）：左摇杆水平，范围 364~1684，中值 1024
5. `gear`（2bit）：`C=0, N=1, S=2`
6. `pause`（1bit）：暂停键
7. `custom_left`（1bit）：左自定义键
8. `custom_right`（1bit）：右自定义键
9. `dial`（11bit）：拨轮，范围 364~1684，中值 1024
10. `trigger`（1bit）：扳机键
11. `mouse_x/mouse_y/mouse_z`（各16bit有符号）：鼠标速度/滚轮
12. `mouse_left/right/middle`（各2bit）：按下状态（值为1视作按下）
13. `keyboard_value`（16bit）：键盘位掩码  
    `bit0..bit15 = W,S,A,D,Shift,Ctrl,Q,E,R,F,G,Z,X,C,V,B`

---

## 4. CRC 校验定义

手册定义为 **CRC-16/CCITT-FALSE**：

1. 多项式：`0x1021`
2. 初始值：`0xFFFF`
3. 输入输出反转：无
4. 异或输出：无

工程实现时建议：

1. 先校验帧头，再做 CRC。
2. 若现场出现字节序差异，可兼容大小端读取帧尾 CRC（提升容错）。

---

## 5. 通信协议文档中的图传相关命令（上层接口）

以下为 2026 通信协议中图传相关命令字（用于上层业务，不是 21B 帧）：

1. `0x0302`：自定义控制器 -> 机器人，30B，上限 30Hz
2. `0x0309`：机器人 -> 自定义控制器，30B，上限 10Hz
3. `0x0310`：机器人 -> 自定义客户端，300B，上限 50Hz（文档注明该协议无重传机制）
4. `0x0311`：自定义客户端 -> 机器人，30B，上限 75Hz

自定义客户端网络参数：

1. MQTT：`192.168.12.1:3333`
2. 协议：Protobuf v3（topic = message 名）
3. 视频流：UDP `3334`，HEVC，UDP 包前 8B 含帧号/分片序号/帧总字节数

---

## 6. 时延与部署约束

1. VT 手册端到端图传延迟：`< 90ms`（实验室环境）
2. 通信协议文档给出的裁判系统数据参考延迟：常态约 130ms，恶劣环境约 200ms
3. 同场多套图传模块并发时建议启用同步运行模式
4. 同环境建议最多 8 套，超出可能出现卡顿或断连

---

## 7. 在当前工程中的落地映射

### 7.1 协议解析模块

1. `components/devices/remote/vt/vt_remote.h`
2. `components/devices/remote/vt/vt_remote.c`

职责：

1. UART 重配置为 `921600 8N1`
2. 21B 帧头校验
3. CRC16/CCITT-FALSE 校验
4. 位域解包为结构化控制量
5. daemon 在线监测与掉线重启接收

### 7.2 CMD 输入后端

1. `applications/infantry/command/infantry_input.c`

职责：

1. 从 `VT_GetCtrl()` 拉取解析结果
2. 若离线/CRC失败则触发 `request_stop`
3. 将摇杆/鼠标/按键映射为底盘、云台、发射命令

### 7.3 配置入口

1. `applications/infantry/config/infantry_config.h`

关键宏：

1. `ROBOT_CMD_INPUT_SOURCE`（切换输入源）
2. `ROBOT_CMD_UART_DATALINK_HANDLE`（图传遥控串口）
3. `CMD_VT_*`（死区、缩放、模式映射等）

---

## 8. 实机联调建议

1. 先抓串口确认帧头固定为 `A9 53`。
2. 验证 14ms 帧周期与在线判定阈值是否匹配。
3. 核对摇杆方向符号与车体坐标方向是否一致。
4. 单独测试 `pause` 急停链路，确认失联与急停行为可预期。
5. 若使用键鼠输入，确认赛事配置中控制源为单一来源，避免双源冲突。

---

## 9. 结论

1. **机器人板侧图传遥控解析以 VT03&VT13 手册 UART 21B 帧为准。**
2. 通信协议文档主要用于图传链路的上层自定义数据交互（`0x0310/0x0311`、MQTT/UDP）。
3. 两文档不是互相替代关系，而是“设备层 + 系统层”互补关系。
